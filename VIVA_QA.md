# Viva Questions and Answers - LankaHomeValue

## What is your project?

LankaHomeValue is an AI-based house price prediction system for Sri Lanka. It predicts the estimated house selling price in Sri Lankan Rupees using machine learning and displays the result through a web application.

## What problem does it solve?

It helps users get a quick estimated house selling price based on house details such as district, area, land size, bedrooms, bathrooms, house size, condition, and facilities. This supports buyers, sellers, and researchers before they perform a formal property valuation.

## What is your prediction target?

The prediction target is:

```text
house_selling_price_lkr
```

This means the model predicts the house selling price in Sri Lankan Rupees.

## Why did you use Gradient Boosting?

Gradient Boosting was selected because it achieved the best R2 score in model evaluation. It is good at learning nonlinear relationships and can combine many weak decision trees to produce a strong prediction model. In this project, it performed slightly better than Random Forest based on R2 score and RMSE.

## What is MAE?

MAE means Mean Absolute Error. It shows the average absolute difference between the actual price and predicted price. A lower MAE means better prediction accuracy.

## What is RMSE?

RMSE means Root Mean Squared Error. It gives higher penalty to large prediction errors. A lower RMSE means the model has fewer large mistakes.

## What is R2 Score?

R2 Score shows how well the model explains the variation in the target values. A score closer to 1 means the model explains the data better. In this project, the best model achieved an R2 score of about 0.9671.

## What technologies did you use?

I used:

- React with Vite for the frontend
- Node.js and Express for the backend
- MongoDB for prediction history
- FastAPI for the Python ML API
- Scikit-learn for model training
- Pandas and NumPy for data processing
- Joblib to save and load the trained model

## Explain the system architecture.

The system has four main layers:

1. React frontend collects house details from the user.
2. Express backend receives the request and forwards it to FastAPI.
3. FastAPI loads the trained machine learning model and predicts the price.
4. MongoDB stores the prediction request and result as history.

The flow is:

```text
React -> Express -> FastAPI -> ML Model
```

## Why did you use FastAPI separately from Express?

FastAPI is used for the Python machine learning model because the model was trained with Python and scikit-learn. Express is used as the main web backend for the MERN-style application and handles frontend communication and MongoDB history.

## Why did you remove price_lkr and price_per_perch from input features?

Those columns can cause data leakage because they directly relate to the target price. If they are used as inputs, the model may learn from information that would not be available during real prediction.

## What is data leakage?

Data leakage happens when the model uses information during training that would not be available during real-world prediction. This can make model accuracy look better than it really is.

## What are the limitations?

- The prediction depends on the dataset quality.
- Real estate market prices change over time.
- Some important real-world factors may not be included.
- The system gives an estimate, not an official valuation.
- The model may be less accurate for locations or property types not well represented in the dataset.

## What are future improvements?

- Add more real property data.
- Use map and geolocation features.
- Add user login.
- Add admin panel for dataset management.
- Add charts and analytics.
- Add automatic model retraining.
- Deploy the full system to cloud platforms.

## Is this an official property valuation system?

No. The system gives an estimated value generated by a machine learning model. It should not be treated as an official valuation.

## How do you store prediction history?

The Express backend saves each prediction request and result in MongoDB. The saved record includes input data, predicted price, price category, and created date.

## How do you check whether all services are running?

FastAPI health check:

```text
GET http://127.0.0.1:8000/health
```

Express health check:

```text
GET http://localhost:5000/api/health
```

The Express health route checks backend, Python API, and database status.
